# Design: Move session_id from URL path param to request body

**Date:** 2026-08-19
**Status:** Approved

## Background

The control plane exposes proxied template/use-case routes under the path
`/sessions/{session_id}/core/templates/...`. The `session_id` is currently
a URL path parameter. The frontend team has requested that it be moved into
the JSON request body instead, so callers pass a flat JSON object rather than
embedding the session identifier in the URL.

## Scope

Only the **POST plugin/template proxy routes** change. Two other route patterns
are explicitly out of scope:

- `DELETE /sessions/{session_id}` — session lifecycle, path param remains correct.
- `GET /sessions/{session_id}/{path:path}` — catch-all proxy for GET traffic
  (health checks, session info). GET requests cannot carry a JSON body; this
  pattern is unchanged.

## Before / After

**Before:**
```
POST /sessions/{session_id}/core/templates/lan/ping
Body: {"host": "192.168.1.1"}
```

**After:**
```
POST /core/templates/lan/ping
Body: {"session_id": "abc123", "host": "192.168.1.1"}
```

The `/sessions/` prefix is removed entirely from plugin/template POST routes.

## Component Changes

### 1. `boardfarm3_control/proxy.py`

Add an optional `body: bytes | None = None` parameter to `proxy_request`. When
provided, use it as the forwarded body instead of reading `request.body()`. This
allows the proxy endpoint to pass a pre-built stripped body (without `session_id`).

```python
async def proxy_request(
    request: Request,
    agent_url: str,
    path: str,
    body: bytes | None = None,
) -> StreamingResponse:
    raw = body if body is not None else await request.body()
    ...
```

**content-length:** When a custom body is supplied the original `content-length`
header is stale (the stripped body is shorter). Strip `content-length` from
the forwarded headers when `body` is not `None`; httpx recomputes it from the
actual bytes passed via `content=`.

### 2. `boardfarm3_control/openapi.py`

#### `_make_proxy_endpoint`

**Signature construction:**

- Remove the `session_id: str` path-param injection from `new_params`.
- Find the `body` parameter in `existing_params` (it carries the original
  Pydantic model generated by the template router generator).
- Create a new Pydantic model `Proxied<OriginalModelName>` that adds a required
  `session_id: str` field alongside all fields from the original model, using
  `pydantic.create_model` and the original model's `model_fields`.
- Replace the `body` parameter's annotation with this new model.

**`proxy_endpoint` function:**

- Extract `session_id` from `body.session_id` (instead of `kwargs["session_id"]`).
- Build stripped body: `body.model_dump(exclude={"session_id"})` → JSON-encode
  to bytes.
- Compute downstream path: `request.url.path.lstrip("/")` (replaces the current
  `split(session_prefix, 1)` logic).
- Call `proxy_request(request, info.agent_url, downstream_path, body=stripped_bytes)`.

#### `register_plugin_routes`

Change route path construction from:
```python
new_path = f"/sessions/{{session_id}}/{route.path.lstrip('/')}"
```
to:
```python
new_path = f"/{route.path.lstrip('/')}"
```

### 3. Agent-side generators — no change

`boardfarm3/api/routers/_generator.py` and `_usecase_generator.py` run on the
agent process and generate routes with no knowledge of `session_id`. These are
unchanged.

## Test Updates

| File | Change |
|---|---|
| `unittests/control/test_openapi.py` | Update assertion: plugin paths no longer start with `/sessions/{session_id}/`. Assert they start with `/core/` (or equivalent). |
| `unittests/control/test_proxy_path_params.py` | Update call URL from `/sessions/s-1/core/templates/lan/0/get_interface_stats` to `/core/templates/lan/0/get_interface_stats`. Add `session_id` to request body JSON. |
| `integrationtests/control/test_proxy_and_lifecycle.py` | GET catch-all tests (`/sessions/{id}/health`, `/sessions/{id}/session`) are unaffected — path param still present for GET routes. |

## Trade-offs

**Body decode overhead:** The proxy previously streamed raw bytes directly from
the request to the agent. After this change, the proxy must JSON-decode the body
to strip `session_id`, then re-encode before forwarding. This is acceptable
because template POST payloads are small JSON objects, not streaming or binary
content.

**Inconsistency between GET and POST:** POST plugin routes have `session_id` in
body; the GET catch-all still has it in the URL. This is a deliberate pragmatic
split — the alternative (query params for GET) would be less idiomatic. The
frontend only calls the POST routes for device operations.
